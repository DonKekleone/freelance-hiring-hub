Buyer Template

A project brief that gives the freelancer something useful to work from.

A good brief does not need to be long. It needs to make the goal, deliverables, constraints and definition of done visible.

Copy-and-fill project brief

Use this as a starting point. Delete anything that does not apply and add project-specific requirements before sending it to a freelancer.

Treat the completed brief as the project's reference point. If the work materially changes later, update the written scope instead of relying on memory.

Project brief structure

Project objective.
Background and context.
Required deliverables.
Target audience or user.
Examples and references.
Technical or brand constraints.
Deadline and milestone dates.
Revision expectations.
Required file formats.
Final handoff requirements.

Write the outcome first

Begin with what the project is supposed to accomplish. This gives the freelancer context for decisions that cannot be captured by a checklist.

Separate requirements from preferences

A requirement must be satisfied. A preference is desirable but negotiable. Mixing the two makes feedback unnecessarily difficult.

A brief should reduce interpretation, not eliminate judgment.The freelancer still needs enough room to apply expertise. Define the target clearly without prescribing every tiny decision.

Use the brief as the reference point

When revisions or scope questions arise later, return to the agreed brief instead of relying on memory.
